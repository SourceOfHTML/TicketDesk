# Prisma 7, through a driver adapter the app cannot opt out of

Persistence is SQLite through Prisma (ADR-0003), and no ticket had pinned a major version. It is **Prisma 7.10.1**, pinned exactly, with `@prisma/adapter-better-sqlite3` — and because Prisma 7 requires a driver adapter, `new PrismaClient()` with no options throws. The adapter is not a performance tweak someone may later remove; it is the only way this app can open its database.

The alternative was Prisma 6 and its built-in Rust query engine, which is the version most tutorials target. It was rejected on two measured findings. The engine's connection pool defaults to `physical_cpus × 2 + 1` — **17 open handles** on an 8-core machine — which is why `?connection_limit=1` exists and why concurrent interactive transactions deadlock at a sharp cliff just above the logical core count. Worse, the engine has an **open, confirmed segfault under Vitest**, which is the runner this project's entire test strategy rests on. Prisma 6 with the adapter was also considered and is genuinely supported (driver adapters went GA in 6.16.0), but Prisma 6's own documentation still describes the Query Engine transforming queries and never claims the engine is bypassed — so that route keeps the pool and the segfault risk while adding a dependency.

## Consequences

- **One connection, no pool.** The adapter holds a single `better-sqlite3` connection, so the deadlock above cannot happen and the test URL carries no `?connection_limit=1`. That parameter is not merely unnecessary under v7 — it would silently become part of the database filename.
- **Foreign keys are enforced on every connection** (`PRAGMA foreign_keys = 1`), so a `Ticket` pointing at a missing `User` fails as `P2003` instead of landing quietly. This is not SQLite's own default; it is something the adapter turns on, which is exactly why it is written down.
- **The CLI no longer loads `.env`.** `prisma.config.ts` calls `process.loadEnvFile()` itself. It is the same primitive `apps/api/src/main.ts` uses, and it takes no dependency. It also defers to an already-set variable, so a per-test-file `DATABASE_URL` override survives it.
- **The version is pinned exactly, and `better-sqlite3` is not a direct dependency.** npm's `latest` tag for the `prisma` CLI currently points at an `8.0.0` release candidate while `@prisma/client` is stable at `7.x`, so an unpinned install pairs an RC CLI with a stable client. The adapter pins `better-sqlite3` to `^12.6.0` while its own latest is `13.x`; installing it directly would nest a second, unused copy.
- **Parameterised raw SQL is unavailable.** An open adapter defect breaks `$queryRawUnsafe`/`$queryRawTyped` parameter bindings, and TypedSQL does not work with this adapter at all. Parameter-free raw statements — the `PRAGMA journal_mode` assertion in the test setup — are unaffected.
